# Frozen build specification v2.0: csv2massing

Frozen 2026-10-06 following the owner's narrowing instruction. This specification supersedes v1, preserved in docs/SPEC_v1_archived.md. Reuse assembled geometry, projection and extrusion modules; their former height ladder is not the CSV height contract. No new ladder, 90-building delivery, SLPK/I3S export, PDF extraction or photorealistic facade work.

## Deliverable and input contract

A Python 3.11 CLI named csv2massing. Offline command takes a CSV, explicit footprint GeoJSON, provenance manifest JSON and output directory. No implicit network calls. Seven City columns, exactly in this order: name,location,height,building_count,floor_area,status,source_pdf. UTF-8, RFC4180 quoting. Heights contain a positive finite number plus explicit m/metres/meters OR a positive integer plus storeys/stories. Blank or unknown is unknown; unitless values are rejected. Metres pass through unchanged. Storeys convert using documented schematic rule 4.0 + 3.0*(n-1) + 1.5 roof metres, so 10 storeys = 32.5 m. No other height fallback; no 4 m placeholder. Floor area is nonnegative finite square metres or blank/unknown, retained as a group value without inferring footprint dimensions. Status is copied verbatim.

Location is the City's supplied location string (address or explicit longitude/latitude text), used as an exact join key, not geocoded or guessed. Each footprint Feature has properties name and location matching the row, a safe string id (also Feature.id), and optional physical_building_id (defaults to id). The GeoJSON FeatureCollection declares crs EPSG:4326 using its standard name object; coordinates are WGS84 longitude/latitude. Each footprint requires a provenance entry keyed by id containing location_point [longitude,latitude], source_url, page, unit, method, reviewer, uncertainty, footprint_source_url, footprint_method and schematic/detailed flag. An unknown reviewer is explicitly unreviewed, never attributed to Amir or the City. Source URL equals source_pdf; page is a positive one-based PDF page number. Synthetic fixtures use test-only URLs and explicit test_only=true.

One CSV row may name a group: building_count must be a positive integer and equals the number of distinct physical buildings in its bound footprint features. Each member receives the row's height; this uniform-height assumption is visible in provenance. Floor area stays the group's supplied value; do not fabricate per-building allocation. A count of two does not produce two copies of one footprint. Separate podium/tower components belong to one physical building and must be supplied as one reviewed footprint feature; duplicate physical IDs and positively overlapping separate footprints are errors. A single schematic prism describes the supplied total building height, never a sum of tower and podium storeys.

Geometry must already be a valid closed Polygon/MultiPolygon with finite coordinates and positive area. Do not silently repair an invalid CSV input. Require the provenance location_point within or on its supplied polygon; otherwise off-footprint. Missing polygons or CRS, wrong CRS, missing bindings, conflicting bindings, duplicate IDs and bad provenance are errors. Do not derive a footprint from a point, floor area, site boundary or bounding rectangle. Existing geometry adapters may project validated polygons to EPSG:26910 for triangulated mesh generation, preserving polygon holes and multipart geometry. Record any explicit simplification; prefer retaining the approved original geometry for this narrow conversion.

## Output contract and validation

Produce massing.geojson, roundtrip.csv with the same seven columns and unchanged input cell values, validation.json and validation.md, provenance/{id}.json, and models/{id}.gltf.

GeoJSON has one Feature per validated physical building with original source fields, row/group count and floor area, height_m, base_height_m=0, extrusion_height_m, height_raw, height_unit, height_method, schematic=true, detailed=false, provenance_file and model_file. Preserve original footprints in WGS84. Unknown height remains JSON null and has model_file=null: write its GeoJSON and provenance record, report missing_height with a plain-language explanation and exit nonzero; no geometry with invented height and no glTF. One glTF for each accepted building with known height. Other invalid rows are rejected, with their row number and plain-language reason retained in validation.

glTF 2.0, self-contained embedded binary buffer, triangles, metre units, right-handed Y-up axes. Convert the reused mesh from east/north/up into east/up/negative-north without reversing winding. Origin is a deterministic per-building projected origin stored with EPSG:26910 and WGS84 anchor in extras, so GIS conversion can georeference it. Include provenance pointer, building ID and schematic/detailed flag. Validate index bounds, finite positions, accessor bounds and lengths, roof/wall/floor geometry and holes.

Each provenance JSON includes id, name, location, source_url, page, input unit, raw height, resolved height or null, exact method/formula, reviewer, uncertainty, status, source PDF, building count, group floor area, footprint source URL/method, geometry hash, schematic/detailed flag and test_only. No claim that a glTF prism is a detailed architectural model. Conversion is deterministic; no current clock or output-directory path in artifacts.

Validation report includes row/input/accepted/unknown/rejected/output/model counts with reconciliation and findings codes missing_height, off_footprint, duplicate_id, wrong_crs and invalid_polygon. Include malformed units/counts/CSV/provenance and missing footprints as plain errors. Exit zero only if all rows pass with known heights; bad data exit nonzero without traceback. Empty data is an explicit error. Never silently overwrite an existing output directory with artifacts; reject nonempty output destination.

## Evidence examples and acceptance gates

1. Ten synthetic sample rows round-trip all seven cells. At least one metre height and one storey height. Generate and inspect one model and provenance per accepted physical building.
2. Metre input 24 m remains 24 m even if legacy height multipliers/config defaults differ; 10 storeys resolves to 32.5 m. Unknown stays null and produces no model.
3. Podium/tower duplicate IDs or overlapping separate footprint records are rejected; one combined building counts once. Group count must reconcile distinct verified polygons.
4. Deliberately bad row rejected with a plain-language terminal error and validation record. Test missing height, off-footprint, duplicate ID, wrong CRS and invalid polygon separately.
5. Two real buildings with explicit public Surrey planning PDF evidence, one-based page and exact unit, independently traceable to the corresponding verified physical footprints. No inferred identity or future plan attached to an unrelated existing footprint. If evidence is missing, stop that example and report the gap; continue source discovery without invention.
6. Document the City GIS conversion and loading step into ArcGIS Online using verified official Esri documentation, including georeferencing, units and provenance retention. This CLI does not build SLPK or I3S. A documented conversion performed by City GIS is distinct from an executed upload.
